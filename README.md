# ai-model-train-lab

New AI architectures, trained from scratch on a laptop and run in the browser. Each model gets a reproducible
`make` pipeline (setup, train, evaluate, checkpoint, sample, export) and a client-side demo on GitHub Pages.

**Live demos:** https://sebastiangolian.github.io/ai-model-train-lab/

| Model | What | Demo |
| --- | --- | --- |
| [`bdh`](#bdh--dragon-hatchling) | Pathway's Dragon Hatchling, a "post-Transformer" architecture, as a byte-level language model on Tiny Shakespeare | [/bdh/](https://sebastiangolian.github.io/ai-model-train-lab/bdh/) |

## Quick start

```bash
make all                      # MODEL=bdh: venv + deps, pinned upstream code, dataset, train, sample, export to web/bdh/
make web                      # serve the demos on http://localhost:8000
```

Requires Python 3.13 (`PYTHON=...` to override) and git. `node` is only needed for the JS parity test.

| Target | What it does |
| --- | --- |
| `make setup` | Create `.venv`, install `requirements.txt`, run the model's `model-setup` (upstream code, datasets) |
| `make train` | Train `MODEL`/`PRESET` into `runs/MODEL/PRESET/` (`checkpoint.pt`, `metrics.csv`, `config.json`, `sample.txt`) |
| `make sample` | Generate from a checkpoint, e.g. `make sample PROMPT='JULIET:\n' TOKENS=600 TEMP=0.7 SAMPLES=3` |
| `make export` | Convert the checkpoint into `web/MODEL/model/` for the browser demo |
| `make web` | Serve `web/` locally |
| `make test` | Run `tests/MODEL` |
| `make models` | List available models |
| `make clean` / `make distclean` | Remove the model's runs / everything generated |

Common variables: `MODEL`, `PRESET`, `DEVICE=auto|cpu|mps|cuda`, `ITERS=N` (override iterations).
Ctrl+C during training saves a checkpoint before exiting.

### Adding a model

1. `models/<name>/model.mk` sets defaults (`PRESET`, `PROMPT`) and a `model-setup` target (upstream code, data).
2. `models/<name>/` provides `train.py`, `sample.py`, `export.py` runnable as `python -m models.<name>.<script>`.
3. `tests/<name>/` and, for a demo, `web/<name>/` plus a card in `web/index.html`.

## BDH — Dragon Hatchling

Wrapper around [pathwaycom/bdh](https://github.com/pathwaycom/bdh), the official toy implementation published with
the paper [The Dragon Hatchling: The Missing Link between the Transformer and Models of the Brain](https://arxiv.org/abs/2509.26507).
Upstream code is cloned at a pinned commit into `vendor/bdh` (MIT, Pathway Technology, Inc.) and not copied here.

> Scope: this is the small byte-level language model from the paper's repository. It is **not** BDH-CQ and does
> not reproduce Pathway's reasoning results (ARC-AGI-1, Sudoku Extreme); those models are not public.

### Presets

| Preset | Layers | D | Neurons/head (N) | Params | Block × batch | Iters | Apple M4 Pro (MPS) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `tiny` | 2 | 128 | 1024 | 1.6M | 128 × 16 | 300 | ~15 s, val 2.66 bits/byte |
| `small` | 4 | 256 | 4096 | 12.7M | 256 × 16 | 1500 | ~20 min, val 2.20 bits/byte |
| `full` | 6 | 256 | 8192 | 25.3M | 512 × 32 | 3000 | upstream defaults, meant for a GPU |

`make train PRESET=tiny` is a quick smoke run; the demo ships the `small` model.

### How the browser demo works

Upstream BDH computes attention in parallel over the whole sequence, without softmax and with `Q = K`:

```
yKV_t = Σ_{s<t} (q_t · q_s) x_s  =  q_tᵀ S_t,     S_t = Σ_{s<t} q_s x_sᵀ   (N × D per head)
```

`web/bdh/bdh.js` uses the right-hand side: a fixed-size "synaptic" state `S` updated once per byte, instead of
re-running the whole prompt for every new token (what upstream `generate()` does) or keeping a growing KV cache.
Because `q` is sparse and non-negative (ReLU), reading and updating `S` only touches the active neurons. The page
shows the live neuron activations per layer.

`tests/bdh/test_web_parity.py` exports a random model, runs the same bytes through PyTorch (parallel form) and
through `web/bdh/bdh.js` in Node (recurrent form), and checks the logits match (max difference ~1e-7).

## Layout

```
models/<name>/    model.mk + train.py, sample.py, export.py, ...
tests/<name>/     tests per model
web/              index.html (model list) + one folder per demo (web/<name>/, weights in web/<name>/model/)
runs/, data/, vendor/   generated by make, not committed
```

The site is deployed from `web/` by `.github/workflows/deploy-pages.yml` on every push to `main`. To publish a newly
trained model: `make train export MODEL=<name>`, then commit `web/<name>/model/`.
